# 视觉、素材、语音与渲染

## 项目目录


中英文分目录，避免工作台语言识别和发布文案串线。

## 渲染前的只读预检（P1）

研究阶段仍先按 `selection_and_research.md` 检查来源记录。素材及 `content_manifest.json` 准备好后、首次渲染或修订重渲染前，再运行不依赖 TTS/视觉服务的预检；只有退出码为0才继续：

```bash
python scripts/preflight_episode.py "$PROJECT" --require-research --require-production && \
python scripts/render_episode.py --manifest "$PROJECT/content_manifest.json" --mode preview
```

预检检查基础结构、字幕正文/分页/显式保护词、素材路径以及研究记录，不联网、不生成语音、不改输入。仍按既有音频指纹选择 `--reuse-audio` 或 `--reuse-tts`，不自动重试付费调用。新制作最终执行 `python scripts/validate_episode.py "$PROJECT" --require-research --require-production`；终检会重新读取当前研究记录并检查实际 SRT，不复用旧 PASS。

旧项目可省略 `--require-research`；未启用的研究合同明确标 `NOT_CONFIGURED`，不回写历史文件。预检 `STRUCTURE_OK` 不是事实、听感或发布通过。旧项目直接入口保持兼容；配置 `production_contract_version: 1` 的新项目直接渲染也会先强制研究与生产预检。两条命令仍须用 `&&` 或显式检查退出码。详细字段与兼容边界见 `automation_contracts.md`。

## 视觉策划

- 进入 TTS 或生图前，先按 `editorial_platforms.md` 完成事实、结构、文字编辑与首读/来源分步复核，保存定稿、材料归属、独立价值及未完成检查。新项目在该交接点按 `selection_and_research.md` 运行研究记录预检并处理结构错误；主张或来源变化后重新检查，`STRUCTURE_OK` 不替代内容审查。没有完成这一交接，不先调用会生成语音的渲染命令。定稿后按语义拆节拍、列视觉清单，不为凑卡片、动效或结尾槽位增加旁白；为时长改稿后须回核受影响主张。卡数按实测单卡≤12秒倒推，先复用已核验素材；不设图片或动画配额。
- 系列层保持手撕纸、印刷肌理和高端杂志感；新闻层重新设计视觉隐喻、配色、镜头与信息层级。
- 封面把当期1–3个题材组成一个有主次的故事，不做等宽三宫格，不放无关主持人或通用地球。
- 内容图只放本节拍需要的短标题、关键数字和问题。若准确文字较多，拆图而不是缩小字号。
- 视觉清单除”用什么图”外，还要为每个事实型节拍写明”静音时必须读到什么”。可选信息锚点包括关键数字、短结论、对比、时间线、因果链、证据原话或问题；纯动作与情绪镜头可留白，但不能连续多卡都只有主体和字幕。**素材身份在选题阶段就标注**（观测证据 / 官方演示 / 旧型号实拍 / 生成示意）以及使用条件是否落实；身份决定叙事取舍和画面可信度，不只是素材数量统计。
- 生图提示词应明确主信息、辅助信息和层级，不要求预留固定字幕带。画面通常只保留一个主结论与少量支撑元素；关键文字优先置于上、中部，下部正常使用环境、纹理、图形、主体或次级文字维持完整构图。用数字卡、对照撕条、时间轴、流程节点、引用框、证据窗、结论章等不同形式匹配题材，不机械复用同一信息框。
- 预览联系表增加“信息密度”检查：遮住字幕快速浏览，若某张事实卡无法辨认数据、论点或证据作用，优先补信息层、拆分节拍或更换构图，而不是增加无意义运动。
- 生图前增加动效节拍表。每个较长内容块至少记录：旁白语义节点、观众此刻应注意的对象、主动作、动作后的可见结果、辅助层、对应重音/音效、稳定阅读区间。若只写得出“淡入、缩放、移动”，说明动效还没有与内容耦合，应继续设计或保持静态。
- 动效节拍表还要单列标题和关键数字的入场方式。标题负责建立新闻身份，关键数字负责制造记忆点，证据层负责完成可信度；三者不同时抢入。优先从当期完整生成图中规划可独立运动的标题牌、数字牌和结果层，逐字复核后再进入透明层合成。
- 标题动画优先使用遮罩揭示、纸片展开、景深让位或印章确认；数字动画优先使用已核验最终数字的滚轴停靠、刻度推进、分组揭示或对比翻面。若没有可靠的中间数值资产，不做真正从零递增的数值重绘，以免动画制造错误事实。
- 15–25秒的长口播必须在自然语义节点拆成多张≤12秒卡；不能仅加字幕页或小动画留在一张长卡。可采用“主体建立—证据响应—结果定格”“数据规模—路径建立—边界翻面”等题材化运动弧；若没有第二个有意义的状态变化，就缩短这张卡或切图。
- 字幕样式预览必须同时覆盖一行、两行、前后 cue 切换和浅色/深色背景。两行底板使用单一自适应容器，或使用完全不相交的逐行容器；禁止依赖会在行间重复叠加 Alpha 的字幕边框实现。先在540p快速检查，再从正式1080p抽取至少一张两行字幕帧确认无黑块、接缝、重影或背景深浅跳变。
- 按交接文档，优先使用工作站 `ai_image_service.generate_image(prompt, size)`；不可用时再用 `apinebula_image_service`。执行环境强制其他生图通道时遵守其工具要求并记录差异。先列资产清单，复用合适旧素材；每资产一次生成，只有文字/事实或明确质量错误才针对性重做，保存工具、提示词、次数与最终选择。关键输出必须目视检查文字、手指、标志、日期和内容相关性。
- 复杂动画使用“完整背景 + 透明 RGBA 图层”。透明图层必须验证真实 alpha，不使用纯黑底抠图冒充可靠透明资产；代码只合成现有位图，不添加新闻标题或说明文字。
- 复杂动画卡优先配置 `animation.engine: scene_v2`。背景不得包含将要移动的同一主体；主体、证据、前景遮挡分别设为 `subject`、`evidence`、`foreground`，通过 `z`、`anchor`、语义 action 和必要阴影形成空间关系。
- 同一复杂卡可有多个错峰 action，但每个 action 必须推动不同语义阶段，并产生可见的场景响应。例如点击动作应包含靠近、按下、目标压缩/发光、数据路径开启和结果稳定；不能只有透明光标缩放。主动作结束后，辅助光效或环境层可以短暂延续，随后整体静止供阅读。
- `scene_v2` 的主动作必须在口播或原声边界前完成收势，并留出可读稳定段；正式渲染会生成 `motion_quality_report.json`，确定性尾部运动和稳定时间不足会阻断新引擎的 release。
- 事实截图保留原始像素。生成视觉框架时预留截图窗，然后确定性合成源截图；不要让 Imagen 重写实时数据。

## 真实视频与原声窗口

0. 入库检查（来源、权利与水印）：先核对原始发布者、素材身份与使用依据，再做全片联系表及四角放大，记录平台水印、账号署名、台标等风险。优先使用可溯源且权利明确的原始素材或获授权版本；无水印镜像不能因画面干净而优先于原始来源，其他文件中的“无水印优先”也只适用于权利已明确的候选。自动扫描只预警，不自动删素材、去标或重做；存在平台风险时向用户说明换源、申诉或保留的选择。平台驳回或用户要求处理，并不替代权利核查；裁切仅用于有相应权利且符合平台要求的编辑，不移除应保留的署名、权利标识或生成内容标识，不掩盖来源。无使用依据时先取得许可、换用合适素材或放弃片段，不以裁切补救。AV1 等新编码源可先转 H264 代理再抽帧；比例和窗口几何另按既有合同计算。
1. 用联系表或候选帧定位片段，确保内容与口播事实直接相关；联系表必须覆盖动作前奏、高潮、结果和人物/现场反应，不能只取固定间隔缩略图。
2. 在相关片段中再按精彩度筛选，优先形成“动作发生—结果出现”或“问题提出—演示回应”的完整小弧线。1.5–4秒只是普通证据片段的起点；比赛、灾害、发布演示等连续动作可保留更长。记录源开始时间、长度、来源、观众新增理解和权利说明。
3. 口播完整结束后插入片段；同一时间点提取源音频，字幕在口播结束时收起。
4. 原声窗口前后使用短淡入淡出。原声音量应接近但不明显压过旁白的感知响度。
5. 横屏素材用自适应主体裁切或宽幅清晰窗加同源模糊背景。目视检查主体大小，不能只依赖公式。
6. 需要让原声真正进入生成场景时使用 `scene_window`，以动作完成后的完整场景作为底图，视频透明淡入淡出；片段结束后恢复同一 settled scene，不能让主体和阴影突然消失。窗口优先用宽高比例描述，并按 `automation_contracts.md` 的剩余可移动距离公式换算左上角位置，不能拿窗口中心占整屏的比例代替。若原片比例与纸框不同，先检查上下或左右 letterbox 是否视觉居中，避免只在一侧形成明显黑条。540p预览与1080p候选都保存静态前、淡入中、稳定播放、淡出末和结束后的对齐联系图，确保生图纸框、预填首帧与真实片段共用同一矩形。

把窗口写进对应卡片的 `original_clip`，不要为每期复制或修改生产脚本。字段和命令见 `automation_contracts.md`；视频与音频可为同一文件，也可分别提供。

## 音频

- 使用阿里自定义女声 `longanlingxin` 和情绪标签。按内容块生成或至少保留提供者逐段时间信息。
- `voice.instruction` 必须包含“中速偏快、利落流畅、句内推进感强、不拖长句尾”。先删冗余，再以快节奏的新闻编辑口吻生成预览；外文名、数字、因果转折和末句仍单独保护。禁止为提速破坏尾音或取消段间呼吸缝。
- 每段裁掉多余首尾静音，但不能删除句中自然停顿。推荐用首端静音裁剪，再反转音频裁尾，避免 `silenceremove` 在第一个句中停顿处截断内容。
- 对每段实测时长后生成时间线；边界以实际可听语音为准，不盲信提供者标注或文本估时。相邻段之间加动态呼吸缝，不零间隔拼接，也不允许下一段提前进入。原声窗口是独立有声区间，旁白在该区间静音。
- 裁剪和混音后逐界听检：上一段已完整收音、下一段没有抢入、没有音节或辅音被切掉。自动波形、ASR 和字幕对齐可用于定位，但不替代实听。
- 末句单独进行完整性和尾音检查，只在最后一个可听音素结束后开始计算0.8秒片尾；不使用 `-shortest` 或任何会按画面名义时长截断末尾语音的封装方式。
- 音乐床保持低于旁白，不用收费音乐；章节提示音克制，不与拟声重复。
- SRT 与去标签口播严格一致。单卡≤12秒范围内的口播使用 `caption_chunks` 按句意分页，每页最多两行；不要把同一视觉节拍拆成一串重复卡片来换字幕，以免动画重启和画面闪回。专有名词误读时同时修口播和字幕，必要时用更易读的同义表达。

## 画面时间线与转场

- 1080×1920、30fps、H.264 + AAC 为默认交付规格。
- 封面静止约0.35秒，招呼继续复用封面。不要在封面和第一条之间增加总结或目录卡。
- 生成图默认静止。只有题材明确需要时才添加一次性语义运动；透明层的出现、点击、盖章、划改或短促震动必须在动作完成后稳定。动画节奏由正常速度下的识别性和阅读时间决定，通常先让一个主动作完整展开，再留稳定画面；多图层必须错峰，不把多个动作挤在开头一瞬间。禁止所有卡片统一 Ken Burns、呼吸缩放或漂移。
- 候选版除联系表外，必须抽查每个复杂卡的动作前、动作峰值、结果态和口播中后段四类帧；同时正常速度观看整卡，确认后半段没有因所有动作过早结束而重新变成“静态海报配长旁白”。
- 复杂卡的覆盖检查至少包含标题建立、关键数字/证据响应和结果稳定三个节点。若标题和数字都在开头完成，口播中段还有新的事实重音，应把第二个状态变化后移或切换新卡，不能用技术上的“稳定时间充足”代替观看节奏。
- 同题通常使用柔和衔接，跨题通常使用更明确但克制的编辑式过渡；具体方式和时长由前后题材、构图方向、语气与节奏决定。0.18–0.30秒和0.30–0.45秒仅为常见起点，过渡帧不得经过纯黑或纯白。
- 末句留在最后新闻的相关画面，自然讲完即可，不强加讨论邀请或创建独立总结图。听检确认末句完整后，再添加0.8秒尾画面和匹配静音，不使用 `-shortest`。

## 发布工作台契约

每个项目根目录必须有 `publish_info.md`，成片在 `final/*.mp4`，封面在 `final/cover*.png|jpg`。发布文案使用解析器可识别的标题：

```markdown
## 标题
**标题文本**
## 简介
观众文案
## 关键词
#标签
```

英文使用 `## Title`、`## Description`、`## Hashtags`。扫描后确认语言、标题、封面、视频和文案均正确，状态为 `publish_ready`。

## 修订最小化

- 只讨论或审阅新稿时，保存到项目 `prompts/`，不要先改正式 manifest、字幕或发布文案，避免与现有 MP4 不一致。进入成片修订后，再把确认稿同步到 manifest，重做受影响语音、字幕和卡片，并重算后续时间线。
- 仅真实片段裁切变化：复用已生成语音和生图，只重做片段与视频封装。
- 仅图片、证据底托、原片窗口位置或动效清单变化：使用 `--reuse-audio`，只看受影响卡、相邻转场和字幕遮挡；不重复深研、TTS与未变化卡的全量逐帧检查。
- 仅删除无效动效：先做540p受影响卡抽查；几何、关键文字或源视频窗口未变化时可直接进入 release，最终仍执行确定性技术验证与内容审核。
- 仅公开文案变化：只改 `publish_info.md` 并重新扫描工作台。
- 不为一个局部修订重新调用全部生图或 TTS。
- 已经被发布工作台或浏览器打开过的正式 MP4 若发生可见画面修订，使用新的版本化 `output_filename`，并把旧正式版移到项目内可恢复的 `preview/archive_*`；`final/` 最终仍只保留一个 MP4。不要只覆盖同名文件后假定播放器一定会丢弃旧分段缓存。

## 三档渲染与缓存

- `--mode preview`：默认540×960/24fps快速校对，跳过边界重检，但不跳过口播、字幕和清单内容一致性。
- `--mode candidate`：1080×1920/30fps全尺寸候选，使用较快编码并检查全部转场边界。
- `--mode release`：1080×1920/30fps正式质量；这是默认模式，也是唯一更新发布 manifest 和 `final/technical_validation.json` 的模式。
- 新一期设置 `production_contract_version: 1` 和 `quality_contract_version: 3`，并提供结构化 `selection_report.json`、每个口播卡的 `purpose` 和 `content_audit.editorial_quality`。V3 的所有语言都要有 `safety_rights_privacy`；中文/中国平台增加 `china_policy`，英文海外版增加 `target_market_policy`。旧 V1/V2 项目保持兼容，不为迁移合同改写历史审核记录。
- 每张静态卡、透明层动画和原声窗口按素材、时长、布局与渲染规格生成内容寻址缓存。候选与发布共享全尺寸中间件；只改未关联内容时复用缓存，不手工判断哪些文件“看起来没变”。
- `preview/build_performance_<mode>.json` 或 `final/build_performance_report.json` 记录阶段耗时、命中率和实时系数。
- 正式制作统一运行 `scripts/render_episode.py --manifest <项目>/content_manifest.json --mode release`；先校对时按 preview → candidate → release 顺序。
- 只换画面、原片窗口布局或转场时使用 `--reuse-audio`；口播不变但需重建裁段/混音时使用 `--reuse-tts`。
- 渲染器支持任意1–3个题材和任意节拍数，不得再写“本期必须8张图”一类单期判断。
- 原声窗口的全屏裁切、完整画面、清晰窗高度/位置、背景模糊及音量都按素材主体动态配置。原声窗口结束后回到对应生成卡片，再进行转场；片尾原声窗口也必须先结束，再显示0.8秒静态尾画面。
- 预览和候选只优化技术检查次数，不得省略最终 `content_audit.json` 或发布前事实、政策与平台审核。
- 质量检查按影响面分层：preview 检查所有改动卡及其前后边界；candidate 重点检查1080p文字、字幕两行、复杂图层和原声窗口；release 运行确定性验证、完整听检与内容/平台审核。未变化静态卡可依据内容哈希复用既有视觉结论，但账号、二维码、水印、平台界面等发布风险扫描仍只预警且每个最终文件执行一次。

## 生图提示词的交付前检查

提示词先写本卡唯一信息任务、可核验事实、逐字文字清单和视觉层级，再写风格；不使用“漂亮背景＋底部字幕”作为画面方案。没有新信息时改分镜，不靠贴纸补数量。

- 文案原样列出，不同时写互相冲突的“几个大字”、部首提示或装饰文字要求。逐字复核实际输出，不能只检查提示词。
- 原始公告、实验输入输出、网页数字与完整排法使用真实证据像素；示意图明确标为示意，不能模拟公告界面当证据，不能用两个圈冒充两个完整解。
- 柱形长度、刻度和面积若表达量值必须按真实比例；生成器无法保证时改成不编码比例的数字对照卡，或合成准确的证据图。单次测试结果不能画成普遍能力排行。
- 封面、口播、信息图和审核稿核对同一组主张；“没有反驳”不能在图里升级成“没注意到”。更换口播后逐卡回核画面，不保留已删除背景的旧图。
- 先看手机尺寸与字幕遮挡，再决定是否加运动；字幕底部不能盖住核心条件、比较标签或结论。透明层没有可读结果或依赖抠黑产生脏边时删除，不以动画配额返工。
- 素材入库记录放在 `source_manifest.json` 对应资产：文件路径、SHA256、来源、使用依据、检查时间、检查帧/四角截图与水印结论。结论绑定文件字节，换源或改图后重查；缺检查不得进入 selected/。自动视觉预警保持只读，人工复核不能写成自动通过。
