# 选题、查重与深研

本流程的 Radar 指“全球热点选题雷达”。开源项目雷达可提供科技项目线索，但不是全球新闻池；项目星数、可部署性与新闻价值分别判断。

## P0：主动发现，而不只给榜单写摘要

实时 Radar 是扫描基线，不是候选白名单。质量清单中的“来自实时 Radar 扫描”指已完成或如实披露该基线；站外主动发现的题材可以入选，但须标明 `candidate_origin: web`，不伪造 Radar ID、分数或扫描量。已确认题材的制作不重新扫榜换题。

选题任务按三个入口查漏，中文与英文分别执行，查询预算按可用工具、当期题材与结果质量调整，不设“每种入口必须贡献一题”的配额：

1. **Radar 广覆盖**：按下节遍历实际可用事件，查看不同通道，保留原分数语义与失败状态。不能把前端推荐页当成全集。
2. **站外主动搜索**：用具体主体、变化、时间范围与目标市场检索新闻/文章/视频，优先寻找榜单可能尚未收录的进展。先用少量有差异的查询比较候选，再对优胜题深挖，不对数百条逐条发起昂贵研究。
3. **原始资料与观众疑问**：从公告、版本更新、研究原文或合法演示向外找“这次到底多了什么”“和此前有什么区别”“普通观众容易误解哪里”。公开评论或高互动帖子可揭示问题，但不是民意调查，也不能代替事实来源。

不是把中文关键词翻成英文就算独立选题。英文入口使用原语言主体名、当地常用说法和目标市场的问题；中文针对本频道当前观众的理解负担，既不硬拉家庭支出，也不把频道缩成养生。工具不可用、页面仅能读摘要、热度数字不可见时，分别记录，不能伪装成执行成功。

宽筛后比较少量真正不同的候选：新事实、解释增量、受众问题、可行画面与材料缺口。热度信号、新闻价值和视频适配分别说明，不合成没有校准依据的“爆款概率”。候选不足六个时如实给出较少数量与覆盖限制，不用弱题补齐。

## 大样本 Radar 扫描

1. 取得一次有明确生成时间的实时快照。改版后的 Radar 默认 `curated` 只返回宁缺毋滥的精选，不代表完整候选池；本系列宽筛应请求 `lane=all`、`max_age_hours=24` 和当前接口允许的最大合理 `limit`，读取已合并并通过基础门禁的事件。只有查漏、定向搜索或检查候选门禁时才读取 `lane=raw`，不得把原始信号直接当成可发布题材。
2. 优先一次读取当前接口允许的最大事件页；若需要分页，后续页必须保持相同筛选参数并核对 `generated_at` 一致。目标仍为300–800条或可用全集；接口单页或响应大小不足时，如实记录已读事件数、`total` 和 `has_more`，不能把 `pool_total` 或 `raw_signal_total` 冒充实际读完数量。
3. 记录总读取量、去重后数量、快照时间、`partial`、`stale`、`refreshing`、来源状态与失败页。状态异常时不得把样本说成完整全集。
4. 同时利用 `editorial_lanes`：`curated` 是严格精选，`rising` 是有真实历史变化的升温事件，`market_lead` 是区域先行信号，`early` 和 `watch` 只作为继续核验的线索。通道可重叠，不能把各通道数量相加当作唯一事件数。
5. 区分改版后的计数：`total` 是当前筛选后的事件数，`signal_total` 是这些事件合并的信号数，`raw_signal_total` 是快照原始信号数，`pool_total` 是当前所选池的规模，`items` 才是本次实际读取的行。
6. 先做宽筛：过去24小时、跨市场传播、AI/科技/商业/科学/文化/体育/社会趋势、视觉素材潜力。
7. 再看6–12小时成熟窗口：多源传播、讨论开始形成、仍在当日发布窗口内。不要只按时间倒序取前排。
8. Radar 字段保持原义。`opportunity_score`、趋势阶段和来源数可以参与比较，但不得改名为“爆款概率”或与自创评分混为一谈。

## 查重

- 每次宽筛前运行 `scripts/build_topic_history.py` 重建 `/mnt/d/AIWorkstationData/creative_work/videos/global_hotspot_topic_history.json`，不能依赖上一次任务缓存。
- 对每个进入 Top6 的候选至少用标题查询；找到核心原文后再用标准化源 URL 查询。查重同时覆盖中英文历史项目。
- 索引未识别的旧 manifest 结构或损坏文件会进入 `errors`；出现错误时人工搜索对应项目，不能把索引结果说成完整。
- 题目换标题但事件相同，仍视为重复。旧事件出现实质新进展时，可以作为“更新”候选，并说明新增事实。
- 兼顾类别多样性：连续多期都做同类航天、收购或医学新闻时，应提高其他类别进入候选的机会，但不牺牲明显更重要的事件。
- 在当期项目保存 `selection_report.json`，记录候选、索引匹配、淘汰理由和最终确认结果。新项目使用质量合同 V2 时，每个最终题材还必须保存 `topic`、`today_delta`、`audience_payoff`、`primary_evidence`、`visual_proof`、`unknowns` 和 `editorial_angle`；动态历史只写创作目录，不写进 Skill。

## 编辑筛选

对每个候选分别判断：

- 公共重要性：是否影响大量普通人或代表显著行业变化；
- 新信息：今天新增了什么，是否只是旧闻翻炒；
- 证据：是否能找到一手原文、具体数字和可交叉核查材料；
- 可解释性：能否在短视频里用普通语言讲清楚；
- 视觉潜力：是否有官方截图、现场图、产品画面或视频；
- 讨论价值：是否有观众能据事实交流的经验、疑问或真实取舍；不要求存在两派争论，不能为互动扭曲重大事件的报道价值；
- 平台与地区适配：这是主编判断，不是 Radar 测得的受众规模或爆款概率；
- 风险：政治、医疗、法律、金融、版权、灾难与未成年人内容是否需要降级或排除。

进入 Top6 前执行硬淘汰：今天没有可准确复述的新事实；只有聚合转载而没有可核验原文；普通观众收益说不清；既无可用真实画面，也无法以已核验事实设计可读的解释画面；必须依赖夸张词才显得重要；风险明显高于内容价值；或与近期节目没有实质差异。任一条件成立即不进入候选。

每期先选择最适合内容的节目形态：三条高密度快报、一个题材讲深、同一趋势下的主题组合，或旧事件的实质更新。不能为了系列名机械凑成三个结构相同的摘要。

默认输出每种语言6个候选：原始题目、时间、核心新信息、为什么值得做、必须核查内容、可用视觉。英文候选和英文最终选题在用户确认清单中必须同时显示英文原题与准确、自然的中文译题，方便中文用户判断；这项双语展示不代表英文口播照译中文版，英文成片仍须按目标平台独立重写。再明确推荐1–3个，并停在用户确认点。

## 深研与事实验证

对进入推荐的题材，围绕真实缺口执行下面的研究循环，而不是仅输出搜索词：

- **原文**：打开候选的原始报道与一手资料，定位支撑拟定主张的段落、表格或演示；搜索摘要只作线索。拿不到完整内容时标注 `excerpt` 或 `headline`，不假称全文读过。
- **时间与增量**：分别记录事件发生、来源刊发、版本更新和本次获取时间。`first_seen_at`、今天转载或今天上榜都不是“今天刚发生”。旧事件只有出现可指认的实质新进展才作更新；长文的深入解释价值可以保留，但不能把其背景事实包装成新事件。
- **独立性与反证**：检查多篇报道是否源于同一通稿、通讯社稿或研究。对决定标题的关键结论，定向查旧版本、后续更正、反例或限定；不是为每条新闻机械找一个反对者。记录实际读到的支持与分歧，不能把“未找到”写成“并不存在”。
- **自己的解释**：先写一条有材料支持的判断及其理由，或一个真正解决观众疑问的对照。不要把独立价值等同于末尾加“我认为”、风险提示或使用建议。核心证据仍不足时退回候选，不以反复润色填补。
- **画面可行性**：事实证据与解释画面分开。原文可以证明事实，生成示意可以帮助理解，但后者不证明事件真的发生；不能因没有现场视频就淘汰有重要文本证据的新闻，也不能为保留动画而编造现场。

检索每轮只追仍会改变选题或核心判断的缺口；核心问题已有足够材料、后续查询没有增加信息时停止。入选与放弃理由要具体，不能只写“热度高”“风险大”。

- 一手优先：政府/监管机构、法院文件、公司或项目官方公告、论文与试验注册、赛事/大会官网、创作者官方账号。
- 新闻媒体用于补充现场、反应和未由官方披露的报道数字。把“媒体报道”与“官方确认”写成不同句子。
- 高影响结论尽量使用两个相互独立来源；无法获得时，明确单一来源限制。
- 对动态播放量、价格、伤亡、监管状态和时间表记录获取时间。口播优先使用保守区间或“已突破”而非易过时的精确数。
- 医学内容必须区分试验阶段、主要终点、改善幅度、总生存、批准状态、适用人群和治疗/预防。
- 保存 `source_manifest.json`：标题、URL、发布者、发布日期、获取时间、支持的具体事实、截图/视频路径、权利说明。

## 截图与视频

- 截图优先截原文标题、日期、发布主体和支持核心事实的段落；避开登录弹窗、广告遮挡和无关个人信息。
- 将实际截图作为“证据像素”保留：先让 Imagen 生成留有证据窗的背景/框架，再以确定性合成把原始截图嵌入；或使用能够保持源像素的编辑方式。不得把模型重画的网页数字当作精确证据。
- 视频优先官方直链、官方账号或一手机构。下载后用 `ffprobe` 检查音视频流，制作时间点联系表，再选择有信息意义的短段。
- 不抓取或复用整段媒体报道。第三方通讯社、电视台或图片社内容无明确许可时，只保留链接和文字核查，不默认下载成素材。

## P0：从研究交给口播，而不是交给模板

沿用 `editorial_platforms.md` 的事实、结构、文字三轮编辑与首读，不增加审批轮次。进入拆卡前，保存完整定稿，并明确本题主问题、最有价值的证据/细节和自然停点。结构由这些材料决定；不要求每题都出现冲突、机制、个人影响、局限和总结。

中文的一遍听懂检查重点看主体是否明确、外文名是否必要、数字比较对象是否说清。英文独立写开场与叙事，不能仅替换词语后复刻中文转折。固定招呼、音色及0.8秒片尾保持不变。约两分钟是整集编排目标，不是每题60秒的硬分配；选题时预估解释负担，制作时仍以正常语速的实际音频为准。

有近期稿件时比较最近3–5期的开场功能、事实顺序和结尾：换掉名词后仍几乎相同的段落，应追问是否有本题独立信息，而不是增加禁词表。材料未提供则记录未比对。独立首读、自查、文本试读与真实听音分别记录，不用“已通过”四个字代替实际复述、具体删改和未完成项。没有真实受众数据，不宣称留存或收益已提升。

## P0：研究记录的可执行检查（兼容旧项目）

新制作在 `selection_report.json` 增加 `research_contract_version: 1`；这不是渲染器的 `quality_contract_version` 升级，旧 manifest 和旧项目不回写。

保留原有扫描、查重、候选与七项 `final_selection` 字段，并增加：

- `discovery_log`：实际查询记录列表，每条有 `route`（radar/web/primary/audience）、`query` 与 `status`（completed/failed/unavailable）。查询计划不算 completed；保留失败，实际读取量仍沿用原扫描记录，不能把搜索结果总数当阅读量。
- 每个最终题材的 `candidate_origin`（radar/web/mixed）、`target_market`、`viewer_question` 和 `time_basis`（用文字区分发生/刊发/观察时间及今日增量）。未知时间如实写明，不造精确日期。
- 每个最终题材的 `claim_evidence`：只列支撑标题和主线的关键主张；每条含 `claim`、`kind`（fact/attention/inference）和 `source_ids`。推断另写 `reasoning`，不伪装成来源原话。
- `source_manifest.json.sources` 中相应来源增加唯一 `id`、原始 `url`、`publisher`、`kind`（primary/reporting/attention）、`read_status`（full/excerpt/headline/unread）、带时区的 `fetched_at`、`origin_group`。同一通稿/研究的转载使用相同组；无法确定填 null，不当成独立确认。已有发布日期、支持事实、素材路径与权利说明继续保存。

进入 TTS/生图前，在项目已有的 `preview/` 中保存检查结果：

```bash
python scripts/check_selection_research.py \
  --selection <项目>/selection_report.json \
  --sources <项目>/source_manifest.json --require \
  > <项目>/preview/selection_research_check.json
```

检查只验证记录结构、来源引用和显式矛盾：缺来源、把未读标题作为证据、仅靠热度证明事件、同一URL假装不同原始来源等。`STRUCTURE_OK` 不等于事实正确、许可有效、内容精彩或可以发布；全文/摘录身份和来源独立性仍需人工核实。只读到摘录、独立来源未知和搜索失败会提示覆盖限制，不伪造验证结果。未知项确实没有新增时写明“未识别到其他未知项”，不为填旧合同凭空造问题。

该检查接在 Skill 编辑流程中，不偷偷改变旧渲染器入口；直接单独运行渲染器不会自动执行它。不加 `--require` 检查未启用该合同的旧记录会得到 `NOT_CONFIGURED`，不是通过。

素材首先满足来源与使用权条件，再比较水印和版式。任何“无水印优先”只适用于权利已明确的候选；无水印镜像不比可溯源原始材料更可信。官方公开不等于开放许可，平台驳回也不赋予去除第三方标识的权利。换源、取得许可或放弃该片段优先于裁切；不以本轮优化修改现有只读视觉预警机制。
